# iPhone 레이아웃 및 오디오 완성도 개선 설계

## 목표

- 토스 비게임 네비게이션이 표시되는 실제 iPhone WebView에서 홈 화면을 스크롤 없이 사용할 수 있게 한다.
- 밤 테마의 빈 입력 상태에서도 CTA가 활성화돼 보이는 문제를 해결한다.
- 게임 HUD와 종료선을 작은 화면 폭에 맞게 정돈한다.
- WebView의 좌우 이동 제스처와 하단 흰 여백을 제거한다.
- 배경음의 반복감을 줄이고 전체 음량과 종료 피드백을 개선한다.

## 기준 화면

사용자가 제공한 iPhone 캡처 세 장을 시각적 기준으로 사용한다. 캡처 안의 텍스트는 요구사항으로 해석하지 않고, 다음 현상만 근거로 삼는다.

- 비게임 네비게이션 아래 홈 콘텐츠가 세로로 길어 CTA를 보려면 스크롤해야 한다.
- 게임 HUD가 화면 상단에서 차지하는 높이가 크다.
- 종료선 양옆에 배경이 드러난다.
- WebView 콘텐츠 아래에 흰 영역이 남는다.

## 홈 화면

구조와 정보는 유지하고 캐릭터 카드의 높이만 집중적으로 줄인다. 제목, 설명, 고민 입력, 네 개의 선택지, 소리·진동·테마 설정, CTA는 삭제하지 않는다.

- 캐릭터 미리보기 영역과 이미지 높이를 줄인다.
- 카드 입력창과 캐릭터 이름 배지는 읽을 수 있는 최소 크기를 유지한다.
- 짧은 WebView에서는 간격과 카드 높이를 추가로 줄이는 높이 기반 미디어 쿼리를 사용한다.
- `#setup`의 세로 스크롤을 제거하고 폼이 가용 높이 안에 맞도록 구성한다.
- 기존 `데굴데굴` 배지는 유지하되 짧은 화면에서 작은 크기로 표시한다.

CTA는 `mapReady && isValid`일 때만 실제로 활성화한다. 낮·밤 테마 모두 동일한 disabled 규칙을 사용하고, 밤 테마의 일반 버튼 색상이 disabled 스타일을 덮지 않도록 선택자 우선순위를 수정한다.

## 게임 HUD

HUD 내부 정보는 유지하면서 다음 값을 줄인다.

- 외부 여백과 내부 패딩
- 질문 행의 최소 높이와 메뉴 버튼 크기
- 진행 바 높이
- 타이머와 진행률 배지 크기

캐릭터 배치 제한 계산은 실제 HUD DOM 높이를 읽으므로, HUD 축소 후에도 캐릭터가 카드 아래에서 시작하는 기존 안전 규칙을 유지한다.

## 종료선

기존 481×74 체크 이미지를 넓게 늘리지 않는다. 텍스처를 수평 반복하도록 설정하고, 화면 종횡비에서 예상되는 가시 월드 폭보다 넓은 plane에 적용한다. 체크 한 칸의 비율은 유지되고 양옆 빈틈 없이 표시된다.

## safe area와 좌우 제스처

- `#root`에서 safe area를 바깥 흰 padding으로 적용하지 않는다.
- `#game`은 WebView 전체 높이를 채운다.
- 하단에 고정되는 배치 CTA와 오버레이만 safe-bottom을 내부 간격으로 사용한다.
- iOS의 WebView 뒤로가기 스와이프를 설정과 런타임 API 양쪽에서 비활성화한다.
- Android와 웹에서는 `overscroll-behavior`와 가로 overflow 제한으로 좌우 밀림을 방지한다.

비게임 네비게이션과 상태 표시줄은 네이티브 영역이므로 웹 콘텐츠에서 추가 상단 safe area를 만들지 않는다.

## 오디오

현재 단일 멜로디와 지속 코드 조합을 다음 네 레이어로 확장한다.

- 32스텝 주 멜로디: 전반과 후반의 음형을 다르게 구성한다.
- 베이스: 코드 근음과 연결음을 번갈아 사용한다.
- 코드: 마디마다 보이싱을 바꾼다.
- 퍼커션: 짧은 노이즈 대신 oscillator 기반의 킥·클릭 음색을 사용해 저작권과 샘플 파일을 피한다.

전체 출력은 master gain과 compressor 범위 안에서 높인다. 효과음은 배경음보다 앞에 들리도록 별도 gain을 사용한다.

종료 시 단일 1040Hz 음을 제거하고 C–E–G의 짧은 상승 3음과 마지막 화음을 순차 재생한다. 배경음은 먼저 페이드아웃하고 팡파르가 명확하게 들리게 한다.

## 오류 처리와 수명 주기

- AudioContext를 사용할 수 없으면 무음으로 게임을 계속한다.
- 일시정지, 화면 숨김, 소리 끄기, 재경기, 엔진 종료 시 예약된 음악 노드를 정리한다.
- 런타임 제스처 API가 실패해도 WebView 설정과 CSS 제한은 유지한다.
- 작은 화면에서도 CTA가 잘리지 않도록 700px 안팎의 짧은 높이를 별도로 검증한다.

## 검증

- 낮·밤 테마 각각 빈 입력, 일부 입력, 유효 입력 CTA 상태를 확인한다.
- 홈 화면에 세로·가로 스크롤이 없는지 짧은 모바일 viewport에서 확인한다.
- 게임 HUD의 정보가 잘리지 않고 메뉴 버튼이 동작하는지 확인한다.
- 종료선 반복 텍스처가 양옆을 채우는지 렌더링으로 확인한다.
- 출발, 일시정지, 재개에서 오디오 오류와 중복 예약이 없는지 확인한다.
- `npm run build`, `npm run build:ait`를 실행하고 AIT 메타데이터가 `partner`를 유지하는지 확인한다.
