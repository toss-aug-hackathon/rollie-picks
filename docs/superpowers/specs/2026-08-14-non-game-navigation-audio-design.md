# 비게임 네비게이션 및 오디오 개선 설계

## 목표

- Apps in Toss 비게임 서비스용 기본 네비게이션 바를 복구한다.
- 기존 효과음을 모바일 WebView에서도 분명하게 들리는 수준으로 높인다.
- 데굴픽의 밝고 가벼운 분위기에 맞는 저작권 걱정 없는 배경음을 레이스 중 제공한다.
- 소리 설정, 일시정지, 앱 가시성 변화와 오디오 수명 주기를 일관되게 연결한다.

## 확인된 원인과 현재 상태

- `granite.config.ts`의 `webViewProps.type`이 `partner`에서 `game`으로 바뀌면서 비게임용 기본 네비게이션 대신 게임용 네비게이션이 적용됐다.
- 설치된 `@apps-in-toss/web-framework` 2.4.5의 웹 설정 타입은 `partner`를 기본 WebView 타입으로 정의한다.
- 현재 효과음은 Web Audio oscillator와 gain `0.05`만 사용해 모바일 기기에서 작게 들릴 수 있다.
- 오디오 컨텍스트는 출발 버튼의 사용자 제스처에서 준비되며, 화면 숨김·일시정지·소리 끄기 때 정지되는 기반 로직이 이미 있다.

## 선택한 접근법

외부 음원 파일 대신 Web Audio API로 데굴픽 전용 배경음을 합성한다.

- 녹음물이나 타사 작곡물을 포함하지 않아 별도의 음원 라이선스와 출처 표기가 필요 없다.
- 네트워크 요청과 음원 파일 다운로드가 없고 앱 용량 증가가 매우 작다.
- 기존 `GameEngine`의 AudioContext 수명 주기와 직접 통합할 수 있다.

대안으로 CC0 음원 파일을 포함할 수 있지만, 라이선스 증빙과 파일 용량 관리가 추가되고 현재 범위에서는 이점보다 관리 비용이 크다.

## 구성 변경

### Apps in Toss 설정

`granite.config.ts`의 `webViewProps.type`을 `partner`로 설정한다. 기존 `navigationBar.withBackButton: true`, `withHomeButton: false`는 유지해 뒤로가기와 앱 닫기 흐름을 토스 비게임 기본 네비게이션에 맡긴다.

화면 스크롤 반동, 새로고침, Android 오버스크롤 제한은 게임 분류와 무관한 현재 UX 설정이므로 유지한다. 화면 세로 고정, 익명 키, Storage, 진동 API는 비게임에서도 제공되는 공개 브리지 사용이며 변경하지 않는다.

### 오디오 그래프

`GameEngine` 내부에 다음 그래프를 한 번만 구성한다.

```text
효과음 소스 ─┐
             ├─ master gain ─ dynamics compressor ─ destination
배경음 소스 ─┘
```

- 효과음: 기존 단음의 개별 gain을 높여 카운트다운과 출발음을 명확하게 만든다.
- 마스터 gain: 전체 출력 수준을 한 곳에서 관리한다.
- compressor: 여러 음이 겹칠 때 피크를 완화해 클리핑을 방지한다.
- 배경음: 짧은 장조 코드 진행과 통통 튀는 멜로디를 낮은 gain으로 반복한다. 효과음보다 작게 유지해 게임 신호를 가리지 않는다.

## 재생 흐름

1. 사용자가 출발 버튼을 누르면 기존 방식대로 AudioContext를 준비한다.
2. 카운트다운 중에는 강화된 효과음만 재생한다.
3. `출발!` 이후 레이스가 실제로 시작되면 배경음을 짧게 페이드인한다.
4. 일시정지 또는 앱이 백그라운드로 이동하면 AudioContext를 suspend해 모든 소리를 멈춘다.
5. 재개하면 컨텍스트를 resume하고 예약된 루프를 계속한다.
6. 우승자 결정, 레이스 초기화, 설정 화면 복귀, 소리 끄기 또는 엔진 파기 시 배경음을 정리한다. 결과 화면에서는 재생하지 않는다.

배경음 스케줄러는 짧은 구간만 미리 예약하고 타이머로 다음 구간을 준비한다. 정지 시 타이머와 활성 oscillator를 모두 해제해 이전 레이스의 음이 다음 레이스에 남지 않게 한다.

## 오류 처리와 호환성

- AudioContext 생성이나 resume이 실패하면 게임은 무음으로 계속 진행한다.
- 이미 닫힌 AudioContext에는 노드를 생성하지 않는다.
- 브라우저 자동재생 정책을 피하기 위해 최초 오디오 준비는 사용자 출발 제스처 안에서 실행한다.
- `document.hidden`일 때 새 음을 예약하지 않고, 복귀 조건이 충족된 경우에만 재개한다.
- 사운드 기능이 꺼져 있으면 배경음과 효과음을 모두 생성하지 않는다.

## 검증 계획

- `npm run build`로 TypeScript와 프로덕션 번들을 검증한다.
- Apps in Toss 빌드 설정에서 `partner` 타입과 네비게이션 설정이 결과물에 반영되는지 확인한다.
- 설정 화면 → 배치 → 카운트다운 → 레이스 → 결과 흐름에서 효과음과 배경음 시작·종료 시점을 확인한다.
- 레이스 도중 일시정지·재개, 브라우저 숨김·복귀, 소리 비활성화, 재경기에서 중복 재생이나 잔류 노드가 없는지 확인한다.
- 데스크톱 및 모바일 뷰포트에서 상단 UI가 비게임 네비게이션 영역과 겹치지 않는지 확인한다.
- 콘솔 오류, 프레임워크 오류 오버레이, 빈 화면이 없는지 확인한다.

## 범위 밖

- 사용자별 볼륨 슬라이더
- 여러 배경음 선택 기능
- 외부 음원 다운로드 또는 스트리밍
- 기존 게임 물리·그래픽·참가자 로직 변경
