# 비게임 네비게이션 및 오디오 개선 구현 계획

## 1. 비게임 런타임 복구

- `granite.config.ts`에서 `webViewProps.type`을 `partner`로 변경한다.
- 기존 비게임 네비게이션 옵션과 스크롤 관련 WebView 옵션은 유지한다.
- 프로덕션 빌드 및 생성 메타데이터에서 게임 분류가 남지 않았는지 확인한다.

## 2. 오디오 출력 구조 개선

- `src/game/engine.ts`에 master gain, compressor, 배경음 gain과 활성 노드 추적 상태를 추가한다.
- AudioContext 준비 시 출력 그래프를 한 번만 구성한다.
- 기존 효과음을 master graph에 연결하고 개별 gain을 높인다.
- 종료된 컨텍스트와 비활성 사운드 상태에서는 노드를 생성하지 않는다.

## 3. 앱 전용 배경음 구현

- 장조 코드 진행과 짧은 멜로디 패턴을 상수로 정의한다.
- 짧은 구간을 순차 예약하는 Web Audio 스케줄러를 구현한다.
- `출발!` 직후 페이드인하고 우승·초기화·종료 시 페이드아웃 또는 즉시 정리한다.
- 일시정지와 화면 숨김은 기존 AudioContext suspend/resume 흐름을 사용한다.
- 타이머와 oscillator를 추적해 재경기에서 중복 재생되지 않도록 한다.

## 4. 회귀 및 수명 주기 점검

- 효과음, 배경음, 소리 토글이 동일한 `soundEnabled` 상태를 따르는지 확인한다.
- 일시정지·재개, 결과, 재경기, 설정 복귀, 엔진 destroy 경로를 점검한다.
- React 컴포넌트 계약 변경 없이 엔진 내부로 변경 범위를 제한한다.

## 5. 검증

- `git diff --check`
- `npm run build`
- 로컬 앱을 열어 설정 → 배치 → 출발 → 일시정지 → 재개 흐름을 실행한다.
- 데스크톱과 모바일 뷰포트에서 빈 화면, 오류 오버레이, 콘솔 오류, 상단 UI 겹침을 점검한다.
- Apps in Toss 네이티브 네비게이션은 설정·번들 근거로 확인하고 실제 토스 샌드박스 검증 범위를 별도로 기록한다.
