# 게임 엔진 초기 번들 분리 구현 계획

## 1. 캐릭터 정의 분리

- `src/game/characters.ts`에 캐릭터 키, 테마, 미리보기 타입과 `CHARACTER_DATA`를 둔다.
- `engine.ts`, `SetupScreen.tsx`, `ResultOverlay.tsx`, `App.tsx`, `GameCanvas.tsx`가 새 경량 모듈을 사용하도록 import를 정리한다.
- 실행 시 필요하지 않은 엔진 참조는 `import type`으로 바꿔 초기 번들에서 제거한다.

## 2. 게임 엔진 동적 로딩

- `GameCanvas`의 최초 effect에서 `import('../game/engine')`으로 엔진 구현을 불러온다.
- import 완료 전 언마운트, 초기화 중 언마운트, 초기화 실패를 각각 안전하게 처리한다.
- 기존 테마 설정, 참가자 동기화, 준비·오류 콜백과 엔진 정리 순서를 유지한다.

## 3. 정적 검증

- `git diff --check`로 패치 형식을 확인한다.
- `npm exec tsc -- --noEmit`으로 타입 오류와 잘못된 import를 검사한다.
- 소스에서 `engine.ts`를 정적으로 참조하는 런타임 import가 `GameCanvas`의 동적 import 외에 남지 않았는지 확인한다.

## 4. 번들 검증

- `npm run build`를 실행한다.
- 변경 전 초기 `main.js` 약 4.76MB·gzip 약 1.67MB와 변경 후 초기 청크를 비교한다.
- 별도 엔진 청크가 생성되고 초기 HTML이 엔진 청크를 선행 로드하지 않는지 확인한다.
- 대형 청크 경고가 남는 경우 의도적으로 지연된 엔진 청크에만 해당하는지 확인한다.

## 5. Apps in Toss 산출물 검증

- `npm run build:ait`로 업로드용 빌드를 생성한다.
- 명령 성공 여부와 생성된 최종 파일 경로를 확인한다.
- 빌드 과정에서 소스 변경이나 예상하지 않은 추적 파일이 생기지 않았는지 `git status`로 확인한다.

## 6. 회귀 확인

- 설정 화면과 기존 `배경 준비 중...` 상태가 유지되는지 확인한다.
- 엔진 준비 후 제출, 배치, 출발, 레이스, 결과, 재경기 흐름을 확인한다.
- 동적 import 또는 엔진 초기화 실패가 기존 오류 UI로 전달되는지 확인한다.
- 자동 검증으로 확인할 수 없는 Toss 실기기 항목은 최종 전달 시 명시한다.
